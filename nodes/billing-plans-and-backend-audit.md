# Billing plans table, Stripe go-live runbook, voucher/vision audit verdicts

From the 2026-06-11 backend audit + build (owner asked to replace Stripe placeholders and audit vouchers/vision).

**Billing is now table-driven.** New `plans` table (schema.sql §15B + migration `20260612000000_billing_plans.sql`): `price_id` pk, `plan_type` (pro|coach), `seat_count`, `active`. Read-only to authenticated users; written only by service role. `create-checkout-session` validates the client's priceId against it (the old hardcoded `PLAN_CONFIG` placeholders are gone), and the pricing page reads price IDs via `subscriptionService.getPlans()` (react-query `['plans']`). Unconfigured plans show a "not available for purchase yet" toast instead of sending fake IDs to Stripe. The function also validates `successUrl`/`cancelUrl` origins against the `ALLOWED_CHECKOUT_ORIGINS` env (comma-separated; warns + allows-all when unset for dev). Removed dead npm deps `stripe` + `@stripe/stripe-js` (frontend never imports them; checkout is a URL redirect) — run `npm install` to sync the lockfile.

**Go-live runbook (operator steps, in order):** (1) Stripe dashboard: create the two recurring Prices ($12 Solar, $99 Coach). (2) `insert into plans (price_id, plan_type, name, seat_count, sort_order) values ('price_…','pro','Oteka Solar',1,1), ('price_…','coach','Oteka Coach',15,2);` (3) `supabase secrets set STRIPE_API_KEY=sk_… STRIPE_WEBHOOK_SECRET=whsec_… ALLOWED_CHECKOUT_ORIGINS=https://yourapp,…` (4) `supabase db push` (plans migration) + `supabase functions deploy create-checkout-session stripe-webhook`. (5) Stripe dashboard: add webhook endpoint `https://<ref>.functions.supabase.co/stripe-webhook` with events checkout.session.completed, customer.subscription.updated, customer.subscription.deleted; its signing secret is the STRIPE_WEBHOOK_SECRET. (6) Test-mode checkout; confirm `users.plan` flips. **Landmine documented in webhook code:** never bump apiVersion past 2024-11-20 without moving `current_period_end` reads to subscription items.

**UPDATE (same day, owner-approved follow-up build):** All scanning gaps fixed + voucher system built.
- *Vision pipeline*: model ids now env-overridable (`VISION_MODELS` csv for the Gemini chain, `PHYSICS_MODEL` for Nebius) — preview retirement is a `supabase secrets set`, not a redeploy. Free-tier limit enforced via `@upstash/ratelimit` fixed-window (`FREE_SCANS_PER_DAY`, default 10) keyed on user id, checked BEFORE any AI spend, premium users exempt, **fails open with a console warning when `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` secrets are unset**. `logs.grams` now stores model-estimated `total_grams` (new prompt field; falls back to item-gram sum then volume_cm3); `volume_cm3` preserved inside tags.
- *Grounding architecture* (`sanitizeAndGround` in vision-pipeline): Layer 1 = physical invariants — type coercion + hard caps (8000 kcal etc.), ≤9 kcal/g energy-density ceiling (corrected when violated), Atwater 4/4/9 reconciliation (derives missing calories; flags >60% drift), item-sum vs total drift check, macro-mass ≤ total-mass. Layer 2 = ~24 cuisine-agnostic per-100g category bands (`FOOD_CATEGORY_BANDS`; model now outputs per-item `category` + `grams`) — out-of-band values are FLAGGED + confidence-penalized, never rewritten, so unusual/international dishes are never blocked. Everything reported in a `grounding` object persisted in tags and folded into `analysis_confidence`. Future Layer 3 (USDA per-item enrichment) intentionally deferred.
- *Vouchers (built)*: `users.plan_expires_at`; `redeem_voucher(p_code)` SECURITY DEFINER RPC (row-locked/race-safe; type pattern `_<N>d` → N-day pro pass; stacks on existing pass; paid subscribers rejected with "already has full access"); hourly pg_cron `expire-premium-passes` downgrades expired passes; Stripe webhook now nulls `plan_expires_at` on purchase/downgrade so paid plans never get cron-downgraded. Migration `20260612010000_voucher_premium_pass.sql` + schema.sql §14. UI: "Have a voucher?" card on the pricing page → `subscriptionService.redeemVoucher` → blanket query invalidation refreshes plan.
- *New secrets for the runbook*: `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (limit enforcement), optional `VISION_MODELS`, `PHYSICS_MODEL`, `FREE_SCANS_PER_DAY`. Redeploy `vision-pipeline` + `stripe-webhook`; `supabase db push` for both new migrations.

**PRICING V2 (2026-06-12, owner-approved):** Strategy: free tier capped at **3 scans/day** (code default changed; `FREE_SCANS_PER_DAY` env overrides) + 2 weeks history (already enforced); **Solar $79.99/yr leading / $12.99/mo anchoring**; **Coach $1,199/yr / $149/mo for 15 athlete seats** (~$6.66–9.93/seat/mo — team discount vs solo without undercutting solo annual); no lifetime SKUs (unhedged COGS); sell via Stripe web checkout, not IAP (15–30% store cut). Implementation: `plans` table v2 adds `billing_interval` ('month'|'year') + `amount_cents` + `currency` — the pricing page renders prices and the monthly-equivalent note FROM THE TABLE (hardcoded strings are only fallbacks), with an annual-default billing toggle whose savings % is computed from real rows. **Auto-trial:** new users get 7-day Solar via column defaults (`users.plan default 'pro'`, `plan_expires_at default now()+7d`) — works because onboarding upserts never pass `plan`; expiry cron downgrades. **Coach seat provisioning (built):** `coach_teams` (owner_id unique, seat_limit 15, 8-char join_code) + `users.coach_team_id`; RPCs `get_my_coach_team` (lazy-create, owner only), `join_coach_team` (seat-limited, row-locked, rejects permanent-access holders, requires owner still 'coach'), `leave_coach_team`, and service-role-only `revoke_coach_team` called by the Stripe webhook on coach downgrade/deletion — members with their own active subscription are spared, others go free. UI: pricing page gains billing toggle, coach "Your team" card (join code + copy + X/15 seats), and the code input now accepts BOTH voucher and team codes (voucher tried first, falls through on 'Invalid voucher code'). Migration `20260612020000_pricing_v2_coach_teams.sql` + schema.sql §15B/§15C. Stripe needs FOUR prices now (Solar M/Y, Coach M/Y).

**Voucher system was: table-only (~10%).** `vouchers` table + one SELECT policy exist; there is NO redemption RPC, NO UI anywhere in src/, NO expiry/benefit mechanics (`users` has no `plan_expires_at`, so 'oteka_plus_30d'-type codes can't expire). Building it needs: a SECURITY DEFINER `redeem_voucher(code)` RPC (atomic check+mark+apply), an entry UI, and a plan-expiry concept + downgrade job.

**Vision pipeline: well-built with known gaps.** Two-stage: Gemini 3 Flash→2.5→Qwen2.5-VL-72B (vision) feeding DeepSeek V3.2 via Nebius→Gemini fallback (nutrition JSON), with circuit breakers, prompt-injection guards on the scene description, hand-width/reference-object calibration, medical-condition injection, an explicit priority micronutrient list, server-side `amount_mg` normalization, and a confidence heuristic. Gaps: (a) all numbers are pure LLM estimates — no grounding against USDA/OFF; (b) no schema validation/sanity clamps on the parsed JSON before DB insert; (c) `grams` column actually stores `volume_cm3` (density≈1 assumed); (d) the free tier's "10 scans/day" promise on the pricing page is NOT enforced anywhere (no rate limiting in any function); (e) `gemini-3-flash-preview` model id is a preview-retirement risk. The file header forbids modifying model config without owner approval.
