# Meal editing: scope, undo-delete pattern, cache reconciliation

Shaped and built 2026-06-11 (brief confirmed by the owner). Decisions:

- **Edit scope (owner decision):** full nutrient editing, but progressive disclosure — default edit view is name + portion stepper (0.25×–10×, scales everything proportionally); exact macro inputs and per-vitamin/mineral amount fields hide behind an "Edit exact nutrients" toggle. The portion model: scaling always applies to *current* values, so hand-edited numbers become the new base. Free for all tiers (data correction is core integrity, not premium).
- **Where:** edit mode transforms the expanded `LogEntryCard` in place — no modal, no route. The card gains an "Edited" pencil provenance glyph (from `metabolic_tags_json.edited_at`) so AI estimates vs. user corrections stay distinguishable. Pending-sync (`isOptimistic`) rows can't be edited/deleted (no server id).
- **Delete = optimistic + undo toast** (`useLogMutations.deleteLogWithUndo`). Implementation detail that differs from the brief's draft: the server delete fires *immediately* (not deferred to toast expiry) and Undo re-inserts the row verbatim via `visionService.restoreLog`, sequenced after the delete settles so they can't race. This avoids unmount-flush hazards entirely. A meal's calibration feedback dies with it.
- **Cache reconciliation:** `useLogMutations` patches every log cache by key-prefix predicate — `['daily-logs']` (gauge/calibration), `['week-logs', …]` (all paged weeks), `['daily-logs-history']`. Insights uses a manual effect and refreshes on next tab visit (accepted staleness). Any future log cache must use one of these key prefixes or add itself to `isLogQuery`.
- **Re-rating:** `useLogFeedback.unlock()` re-opens submitted calibration sliders; resubmit goes through the same `updateLogFeedback` path (engine gets updated weights).
- **Dirty-draft protection (added in the follow-up harden):** `useEditingLogs` (`src/lib/state/editingLogs.ts`, zustand micro-store) counts cards in edit mode. The dashboard refuses tab switches, week paging, Today, and date-strip selection while count > 0 (toast: "Finish editing your meal first") — these would unmount the card and silently discard the draft. Cards register via a `useEffect(isEditing)` whose cleanup covers every exit path. Esc on a dirty draft arms a 4s "press Esc again to discard" toast instead of discarding instantly; clean drafts close immediately. Focus hands into the name input on `beginEdit` and back to the `edit-meal-{id}` button on save/cancel. Any future container that can unmount log cards must add the same guard.
- **Backend verified against `src/lib/db/schema.sql` (no migration needed):** RLS policy `"Logs manage own" ON logs FOR ALL USING (auth.uid() = user_id)` covers select/insert/update/delete — updateLog, deleteLog, and the undo re-insert all pass. `logs.id` is `bigint generated BY DEFAULT as identity`, so restoreLog's explicit-id insert is legal. `idx_logs_user_date (user_id, local_date)` is exactly the composite index the week-range queries need. `edited_at` lives inside the `metabolic_tags_json` JSONB — no column added. Type nit: the DB id is bigint (arrives as a JS number) while `LogEntry.id` is typed `string?` — harmless everywhere it's used, but don't write code that assumes string methods on it. Caveat: this verifies the repo's declared schema, not whatever is deployed — confirm the security-hardening migration/schema has actually been applied to the live project.
- **Legacy data shape gotcha:** old rows wrap macros in `tags.macros`; new rows are flat. `saveEdit` writes to whichever shape the row has, and always writes both `food_name` and `item` (readers use either). Deferred: storage image GC for deleted meals; micros `amount` strings aren't auto-scaled by the portion stepper (units live in the string), only `daily_value_pct` scales.
